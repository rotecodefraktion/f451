Backup & Restore — SAP HANA auf Azure

Verbindliche Sicherungs- und Wiederherstellungsprozedur für die produktiven HANA-Systeme in der Region West Europe. Gilt für Datenbank-, Log- und Dateisystemsicherung sowie für den quartalsweisen Restore-Test.

01Geltungsbereich

Die Prozedur gilt für alle Systeme mit Backint-Anbindung an einen Recovery Services Vault. Systeme ohne Backint (Entwicklungssysteme, Sandkästen) sichern ausschließlich dateibasiert nach Blob-Speicher und sind hier nicht abgedeckt.

HANA QualitätssicherungHDQQS14 Trsv-sap-qs-weu

02Sicherungswege

Datenbanksicherungen laufen über den Backint-Agenten direkt in den Vault; das Dateisystem /hana/shared wird getrennt davon wöchentlich in einen Blob-Container gesichert und nach 90 Tagen in die Archivstufe verschoben.

03Vollsicherung anstoßen

Eine außerplanmäßige Vollsicherung ist vor jedem Kerneltausch und vor jedem Einspielen eines Support-Package-Stacks Pflicht. Der Aufruf erfolgt auf dem Datenbankknoten als Benutzer hdbadm.

  1. Freie Kapazität im Vault prüfen — unter 15 % zuerst alte Wiederherstellungspunkte freigeben.
  2. Vollsicherung der Systemdatenbank und jedes Mandanten anstoßen.
  3. Auftragsstatus verfolgen, bis Completed gemeldet wird.
  4. Sicherungskatalog gegen M_BACKUP_CATALOG abgleichen.
hdbadm@sap-hdb-01 — bash Kopieren⌘ C 
# Vollsicherung der Systemdatenbank über Backint
hdbsql -i 00 -d SYSTEMDB -u SYSTEM -p "$HDB_PW" \
  "BACKUP DATA USING BACKINT ('VOLL_$(date +%Y%m%d_%H%M')')"

# Danach jeden Mandanten einzeln
for DB in HDB S4P; do
  hdbsql -i 00 -d "$DB" -u SYSTEM -p "$HDB_PW" \
    "BACKUP DATA FOR $DB USING BACKINT ('VOLL_${DB}_$(date +%Y%m%d)')"
done
Hinweis

Das Kennwort steht nicht im Skript, sondern kommt aus dem hdbuserstore-Eintrag BACKUP. Für automatisierte Läufe -U BACKUP statt -u/-p verwenden.

04Wiederherstellung prüfen

Der Restore-Test läuft quartalsweise auf dem QS-System. Er gilt nur dann als bestanden, wenn die Datenbank danach ohne Fehler in den Zustand GREEN zurückkehrt und der Sicherungskatalog lückenlos ist.

Azure CLI — Wiederherstellungspunkte Kopieren⌘ C 
az backup recoverypoint list \
  --resource-group rg-sap-prod-weu \
  --vault-name rsv-sap-prod-weu \
  --container-name "VMAppContainer;compute;rg-sap-prod-weu;sap-hdb-01" \
  --item-name "SAPHanaDatabase;hdb;systemdb" \
  --output table
Nicht auf dem Produktivsystem ausführen

RECOVER DATABASE überschreibt den laufenden Datenbestand ohne Rückfrage. Der Restore-Test läuft ausschließlich gegen HDQ; die Freigabe für einen produktiven Restore erteilt die Bereitschaft.

Wie das Theme technisch greift

Die Rohwerte liegen ausschließlich als --l-* / --d-* in einem einzigen Block; die Themes weisen sie nur zu (--color-bg: var(--l-color-bg)). Abgeleitete Flächen wie Chip-Hintergründe entstehen über color-mix() aus denselben Variablen — ein Anwender-Theme tauscht Werte, nie Regeln. Kein Baustein enthält einen Hex-Wert oder eine px-Angabe.
